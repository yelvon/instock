# 部署命令速查

**仓库根目录**：含有 `requirements.txt` 与 `instock/` 子目录的那一层。下文 `$REPO` 表示该路径（例：`/Users/fwj/stock/instock`）。

详细说明、排障与 Cookie 配置见 [部署说明.md](./部署说明.md)；Docker 日常运维见 [docker运维.md](./docker运维.md)；上手流程见 [快速开始.md](./快速开始.md)。

## Docker 开发挂载：代码 / 前端更新后如何看到页面

使用 **`docker-compose.dev.yml`** 挂载本机仓库时：

- 只改 **Python/Vue 代码**：可用 `--quick` 仅 restart（快）。
- 改了 **`docker/.env`、`docker-compose.yml`、通达信挂载**：必须用默认模式 **重建 InStock**（`restart` **不会**注入 `INSTOCK_TDX_DIR` 等新环境变量/卷）。

**一键脚本**（在 `$REPO` 下）：

```bash
./scripts/docker_dev_reload.sh              # 默认：构建前端 + 重建 InStock（推荐）
./scripts/docker_dev_reload.sh --pip        # 同上，并在容器内 pip install 依赖
./scripts/docker_dev_reload.sh --quick      # 仅 restart（不刷新环境变量与 /tdx 挂载）
./scripts/docker_dev_reload.sh --skip-npm   # 跳过前端构建
```

脚本会读取 **`docker/.env`**（含 `INSTOCK_TDX_DIR_HOST`），删除旧 `InStock` 后用 `--no-deps` 创建新容器，**不碰**已运行的 `InStockDbService`，避免容器名冲突。

等价手动步骤（应用通达信挂载时）：

```bash
cd $REPO/instock/web/vue-app
npm ci && npm run build

docker stop InStock && docker rm InStock
cd $REPO/docker
export INSTOCK_REPO_ROOT=$REPO
# 确保 docker/.env 中 INSTOCK_TDX_DIR_HOST=~/tdx-docker-mount
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --no-deps instock
docker exec InStock printenv INSTOCK_TDX_DIR   # 应为 /tdx
```

浏览器访问：**http://localhost:9988/instock/app**（首页 **`/instock/app/home`**；任务中心 **`/instock/app/jobs`**；数据同步 **`/instock/app/sync`**）。

> 未挂载本机代码、仅用 Hub 镜像时：宿主机 `npm run build` **不会**进入容器，需 **`docker compose pull` + `up -d`** 或本地 **`docker build`** 自建镜像。详见下文「Docker Compose」与「Docker + 本机代码挂载」。

## 本机 Python

| 目的 | 命令（均在 `$REPO` 下执行） |
|------|-----------------------------|
| 装依赖 | `python3 -m pip install -r requirements.txt` |
| 首次建库表 | `python3 instock/job/init_job.py` |
| 启动 Web | `python3 instock/web/web_service.py` → 浏览器 **http://localhost:9988/** |
| 日作业（默认交易日） | `python3 instock/job/execute_daily_job.py` |
| 仅快照 | `python3 instock/job/basic_data_daily_job.py` |
| 单日 / 多日用参 | 见 [快速开始.md §4](./快速开始.md) |

**代码更新后**：`git pull` → 视情况 `pip install -r requirements.txt` → **重启** Web / 作业进程。

**数据库连接**：改 `instock/lib/database.py` 或用环境变量 `db_host`、`db_user`、`db_password`、`db_database`、`db_port`。

## Docker Compose（默认：镜像内代码）

在 **`$REPO/docker`** 目录：

| 目的 | 命令 |
|------|------|
| 首次准备数据与空配置（路径可改，与 deployment 一致） | `mkdir -p ~/instock-docker/mariadb/data` && `touch ~/instock-docker/instockproxy.txt ~/instock-docker/eastmoneycookie.txt` |
| 首次 Compose 前确保网络存在（`compose.yml` 中 `InStockService` 为 external） | `docker network create InStockService`（若提示已存在可忽略） |
| 启动 | `docker compose up -d` |
| 停止 | `docker compose stop` |
| 停并删容器 | `docker compose down` |
| **容器名冲突**（`InStockDbService` / `InStock` already in use） | 删的是**容器壳子**，不是库文件。MariaDB 数据在宿主机 **bind mount**（默认 `~/instock-docker/mariadb/data`），`docker rm -f InStockDbService InStock` **不会动该目录**；随后 `docker compose up -d` 会新建容器并**挂回同一目录**，数据仍在。**不要**对数据目录执行 `rm -rf`，也不要在未确认前 `docker volume prune`。 |
| 拉新镜像再起 | `docker compose pull` && `docker compose up -d` |
| 看应用日志 | `docker logs InStock --tail 100 -f` |
| 看库日志 | `docker logs InStockDbService --tail 100 -f` |

**访问（默认进入 Vue SPA）**：根路径 **`http://localhost:9988/`** 会 **302** 到 **`http://localhost:9988/instock/app/home`**。常用子路径：`/instock/app/sync`（数据同步）、`/instock/app/jobs`（任务中心）、`/instock/app/table?table_name=…`（数据表）、`/instock/app/indicators?code=…&date=…`（指标）。旧路径 `/instock/data`、`/instock/data/indicators`、经典首页 `/` 均会重定向到上述 SPA。回测二期契约见 [回测-api契约.md](./回测-api契约.md)。

**自建镜像**：`docker/Dockerfile` 已含 **Node 多阶段构建**，`docker build` 时会自动执行 `npm ci` + `npm run build`，无需在宿主机先产出 `vue-dist`。若仍使用 **Docker Hub 上的旧镜像**（如 `mayanghua/instock:latest`），需确认发布方是否已打入新版前端；否则请本地 `docker build` 并改 `compose` 中的 `image` 指向自建镜像。

**代码更新后**：若**未**挂本地代码 → `git pull` 只影响宿主机；要镜像里新代码需 **`compose pull` + `up -d`**。若已挂本地代码 → 见下一节，一般 **`restart instock`** 即可。

## Docker + 本机代码挂载（开发）

**必须先设环境变量**（与 `up`、`restart`、`down` 等**所有**带 `docker-compose.dev.yml` 的命令在同一终端里执行前都要有效）：

| 目的 | 命令 |
|------|------|
| 宿主机脚本可执行（首次） | 在 `$REPO`：`chmod +x instock/bin/run_web.sh instock/bin/run_job.sh instock/bin/run_cron.sh` |
| 指定仓库根（**必须为绝对路径**） | `export INSTOCK_REPO_ROOT=$REPO`（例：`export INSTOCK_REPO_ROOT=/Users/你/instock`）；未设置会报错：`required variable INSTOCK_REPO_ROOT is missing a value` |
| 一行指定（可不先 export） | `INSTOCK_REPO_ROOT=$REPO docker compose -f docker-compose.yml -f docker-compose.dev.yml …`（把末尾换成 `up -d` / `restart instock` 等） |
| 启动（挂本机代码） | 在 `$REPO/docker`：`export INSTOCK_REPO_ROOT=$REPO` 后执行 `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d` |
| 改代码后重启应用 | 同样在 `$REPO/docker`：**先** `export INSTOCK_REPO_ROOT=$REPO`，再 `docker compose -f docker-compose.yml -f docker-compose.dev.yml restart instock` |

`INSTOCK_REPO_ROOT` 仅给 **Compose 解析 `docker-compose.dev.yml` 用**：把宿主机 `$REPO` 挂到容器内 **`/data/InStock`**。

## 容器内跑一次作业（Compose 已起）

```bash
docker exec InStock python3 /data/InStock/instock/job/execute_daily_job.py
```

其它脚本把末尾路径换成 `instock/job/xxx.py` 即可。
