# 分阶段路线图

本文档定义优先级与阶段目标，与各层级详细条目（`data.md`、`backtest.md` 等）交叉引用。

## 阶段 0：基线确认（持续）

- 清点当前默认可用的 job 组合（含 `execute_daily_job.py` 中启用/注释步骤）。
- 文档化：最小可运行数据流、Web 访问方式、环境变量清单。
- **产出**：根 README 或 `docs/plan/repo-alignment.md` 与真实行为一致。

---

## 阶段 1：数据可长期维护（高优先级）

**目标**：增量、幂等、校验、备份、存储基线到位。

**主要对应**：`data.md` 第 1–4、6–8 节；`ops-scheduling.md` 第 1、4、5、7 节。

**建议里程碑**

1. 核心行情表幂等键与 upsert 路径统一。
2. 每日校验报告（可先落日志/CSV，再落库）。
3. 备份与恢复文档 + 一次演练记录。
4. 大表分区/索引评审与实施（按数据量触发）。

---

## 阶段 2：可复现回测（高优先级）

**目标**：统一回测入口、成本与规则、结果与参数可追溯。

**主要对应**：`backtest.md` 全文；`strategy.md` 第 1、3 节。

**建议里程碑**

1. 选定主回测范式并实现最小引擎 + 双均线示例。
2. 成本与 T+1/涨跌停/停牌行为测试覆盖。
3. 回测运行元数据表或文件规范（含 `params_hash`）。

---

## 阶段 3：策略工程化（中优先级）

**目标**：插件化、测试、与因子/指标流水线协同。

**主要对应**：`strategy.md` 第 2、4、5、6 节；`data.md` 第 5 节（元数据）。

**建议里程碑**

1. 策略注册表 + 示例插件目录。
2. 策略 fixture 测试纳入 CI。
3. （可选）因子表与策略只读 API。

---

## 阶段 4：可观测与运维体验（中优先级）

**目标**：编排可视化、日志规范、危险操作受控。

**主要对应**：`ops-scheduling.md` 第 2、3、5、6、8 节；`web-tools.md` 第 2、5 节。

**建议里程碑**

1. 编排 run 元数据持久化。
2. Web 或 CLI 查看最近运行与错误摘要。
3. logrotate 或应用内日志切割。

---

## 阶段 5：产品化 Web 与进阶研究（低优先级）

**目标**：回测队列、结果对比、Walk-forward 等。

**主要对应**：`backtest.md` 第 7 节；`web-tools.md` 第 3、4、6 节。

---

## 优先级矩阵（简表）

| 紧急重要 | 重要不紧急 |
|----------|------------|
| 数据幂等与校验 | 分区与归档 |
| 编排与失败可定位 | Walk-forward |
| 回测规则与复现 | Web 回测队列 |
| 备份恢复 | 多数据源熔断 |
