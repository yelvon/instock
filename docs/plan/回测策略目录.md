## 3. 新增内置策略

1. 在 `strategies/` 新建 `my_strategy.py`，继承 `Strategy`，实现 `next(date)`。
2. 在 `builtins_catalog.py` 的 `_technical_catalog()`（或新分组函数）增加 `StrategyCatalogEntry`：
   - `strategy_id`、`strategy_cls`、`title`、`description`、`category`
   - `param_defs`：`ParamDef(key, label, type, default, min=, max=)`
3. 运行单测：`PYTHONPATH=. python3 -m unittest tests.test_backtest_registry -v`
4. 重启 Web；在 `/backtest` 下拉确认。
5. 更新本表与 `AGENTS.md` §2 内置 id 列表。

---

## 4. 新增插件策略

1. 复制 `plugins/example_hold.py` → `plugins/my_strategy.py`，取消注释并改写。
2. 模块末尾调用 `register(..., category="plugin", param_defs=[...])`。
3. 可选：`INSTOCK_STRATEGY_PLUGINS=包.模块`（逗号分隔）。
4. 插件加载失败会写 `warning` 日志；`INSTOCK_STRATEGY_PLUGINS_STRICT=1` 时启动失败。

---

## 5. 参数校验

- 服务端：`registry.validate_params()`，创建回测前与 `run_backtest` 内调用。
- 前端：`utils/strategyForm.ts` 提交前校验（与后端规则一致部分）。
- 策略级规则示例：双均线 `fast < slow`、RSI `oversold < overbought`。

---

## 6. 与选股 job 的关系

| 方式 | 用途 |
|------|------|
| `strategy_data_daily_job` + `core/strategy/check_*` | 日批写入 `cn_stock_strategy_*` |
| `screening_*` 回测策略 | 回测区间内用历史 K 线调用同一 `check_*` |

修改 `check_*` 后，应同时验证日批表与对应 `screening_*` 回测项。

---

## 7. 禁止事项

- 策略内 **禁止** import Web、写数据库。
- 勿与 `core/strategy/` 日批选股混为同一 API。
